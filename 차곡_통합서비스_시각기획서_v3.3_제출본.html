00 · 한 장 요약

이 페이지만 읽어도 됩니다

문제

간헐적인 증상은 말로 전달되지 않습니다

“브레이크 밟을 때 가끔 끼익 해요.” “언제요? 속도는요? 지금은 안 나는데요.” 증상이 난 조건을 운전자는 기억하지 못하고, 정비소 시운전에서는 재현되지 않고, 가족 중 다른 사람이 같은 증상을 처음처럼 겪습니다.

해결

조건을 차가 기억하고, 다시 오면 먼저 말합니다

“방금 그 소리 기록해” 한마디에 앞 20초·뒤 10초의 브레이크·조향·내비 안내 상황을 저장합니다. 같은 문제에 기록이 2건 이상 쌓여 잠정 패턴이 생기면, 그 조건에 다시 들어갈 때 차가 먼저 알립니다. 알림 뒤 운전자가 느꼈는지가 쌓이면서 민감도가 조정됩니다. 차곡은 소리를 듣는 것이 아니라, 소리가 났던 순간의 차량 상태를 기억합니다. 기록은 가족에게 이어지고 수리 후 확인까지 한 사건으로 관리됩니다.

시연 3장면무엇을 보여주나쓰는 신호
1. 순간 기록“기록해” → 앞뒤 30초 차량 상태가 한 건으로 저장Brake · SteeringWheel · Odometer · NaviHelper 안내 상황
2. 재현 알림같은 조건 진입 직전, 차가 먼저 “지난번 그 조건이에요”같은 신호 + 3단계 규칙 판정 (차 안)
3. 인계와 해결다음 운전자가 탈 때 브리핑 → 정비 → 수리 후 확인 → 해결Fuel · Odometer · 사용자 입력

왜 차량 앱이어야 하나

“브레이크를 밟는 중이었는가”는 휴대폰이 알 수 없습니다. 조건 재진입을 주행 중에 감지해 먼저 말하는 것도 차 안에서만 됩니다. 탑승 순간에 이전 운전자의 기록을 듣는 경험도 차량에서만 자연스럽습니다.

현대차가 얻는 것

블루링크 선제케어가 차량 데이터로 이상 징후를 감지한다면, 차곡은 차량 데이터만으로 설명하기 어려운 운전자의 체감 증상을 발생 조건과 함께 남깁니다. 원격 진단이 포착하기 어려운 간헐 증상을 정비 과정에 쓸 수 있게 보완합니다.

우리 차에서 생긴 일을, 다음 사람이 처음부터 다시 겪지 않게 합니다.

01 · 기획 의도

v2에서 v3로 축을 하나로 줄이고, v3.1에서 근거를 채웠습니다

v2는 ‘차량 관리’와 ‘운전 성장’ 두 축이었습니다. 두 축은 사용자·공개 범위·동기가 달라 문서 안에서 계속 벽을 세워야 했고, 성장 축은 아직 풀지 못한 운전자 식별 위에 서 있었습니다. v3는 차량 특화성이 가장 강한 ‘차량 관리’ 하나를 척추로 세우고, 운전 성장은 그 위에 얹는 한 줄로 줄였습니다.

v2에서 유지

관리 노트와 상태 흐름

출처 구분(사용자 입력 / 차량 수신), 새 증상 → 확인 → 정비·확인 중 → 해결 ↩ 재발, 수리 후 확인. 그대로 가져옵니다.

v3에서 추가

능동형 재현 알림

v2의 ‘수리 후 확인’은 정차 후 통계였습니다. v3는 조건 진입 직전에 차가 먼저 말합니다. 수리 전에는 재현을 돕고, 수리 후에는 재발 확인을 돕습니다.

v3에서 축소

운전 성장은 배지 한 줄

코스·가중치·XP는 확장 섹션으로 내립니다. 첫 버전은 인수인계 브리핑에 붙는 습관 배지 1종만 둡니다. 팀원 아이디어를 버리는 것이 아니라 순서를 미루는 것입니다.

첫 사용자

차 한 대를 번갈아 쓰는 가족. 출퇴근을 나눠 하는 부부, 주말에 부모 차를 쓰는 성인 자녀. 혼자 쓰는 차에서도 순간 기록과 재현 알림은 그대로 동작합니다.

02 · 세 기둥

기록하고, 차가 기다리고, 가족에게 이어집니다

기둥 1

순간 기록

차량 상태를 차 안에서 계속 짧게 보관하다가, 운전자가 말한 순간의 앞 20초·뒤 10초만 남깁니다. 음성이 없을 때는 주행 중 최근 몇 분(초안 10분)을 순환 보관했다가 정차 후 시점을 고르게 하고, 고르지 않으면 폐기합니다. 정차 후 “끼익, 앞쪽에서” 같은 한 줄 묘사를 덧붙이고, 기존 미해결 문제에 연결할지 새 문제로 둘지 사용자가 정합니다. 소리 원음은 저장하지 않습니다.

기둥 2

재현 알림

같은 문제로 묶인 기록이 서로 다른 주행에서 2건 이상 겹치면 잠정 패턴(브레이크 유지 시간 + 조향 범위 + 내비 안내 상황)을 만들고, 그 조건에 다시 들어갈 때 한 번 알립니다. 1건일 때는 조건 후보로만 두고, 운전자가 “다음에 알려줘”를 켠 경우에만 알립니다. 주행 중에는 알리기만 하고, 났는지는 정차 후 묻습니다. 수리 전 알림은 “지금도 나면 기록해”, 수리 후 알림은 “확인 조건을 지나고 있어요”이고, 났는지는 두 경우 모두 정차 후에 묻습니다.

기둥 3

가족 인수인계

다음 운전자가 탈 때 정차 중에 차량 상태, 새 메모, 미해결 사항을 30초 안에 듣습니다. 읽은 것과 해결된 것은 다르게 다루고, 같은 안내를 반복하지 않습니다.

새 증상→확인함 · 미해결→재현 알림 (수리 전)→정비 · 확인 중→재현 알림 (수리 후)→사용자가 해결 기록↩ 재발하면 다시 열기
기록 없음과 증상 없음은 다릅니다. 같은 조건을 몇 번 지났는지와 운전자가 증상을 느꼈는지를 분리합니다. 무응답으로 문제를 닫지 않고, 해결은 사용자가 기록합니다.
02-1 · 재현 알림은 어떻게 판정하나

소리를 듣는 것이 아니라, 소리가 났던 조건을 비교합니다

차량 신호만으로 끼익 소리가 실제로 났는지는 알 수 없습니다. 차곡이 판정하는 것은 “과거에 소리가 났다고 기록된 주행 조건과 지금이 얼마나 비슷한가”입니다. 판정은 세 단계로 나누고, 마지막 단계는 반드시 사용자가 맡습니다. 그리고 알림 뒤 운전자가 느꼈는지를 세 카운트로 계속 쌓아 민감도를 조정합니다.

같은 문제인지는 사람이 정하고, 조건 비교는 그 안에서만 합니다. 민지의 “앞쪽 끼익 소리”와 준호의 “브레이크 밟을 때 진동”은 차량 상태가 비슷해도 같은 고장이 아닐 수 있습니다. 첫 증상 등록 때 문제 ID를 만들고, 이후 기록은 사용자가 기존 미해결 문제에 연결하거나 새 문제로 등록합니다. 조건 비교는 같은 문제 ID에 묶인 기록끼리만 합니다.
1단계 · 조건 후보

기본 필터를 지나고, 기록값과 비슷한가

두 겹입니다. 먼저 기본 필터(브레이크 1.5초 이상, 조향각 10° 이하)로 흔한 주행을 걸러내고, 그 다음 Issue별 조건 프로파일에서 실제 기록값의 범위(예: 브레이크 1.8~2.4초, 조향 −3°~+8°)에 허용 오차를 더한 범위와 비교합니다. 기본 필터만 쓰면 브레이크를 좀 길게 밟는 모든 주행이 잡히므로, 프로파일 비교가 조건을 좁히는 역할입니다. 허용 오차는 P0에서 정합니다.

2단계 · 잠정 패턴

다른 주행 2건 이상이 겹치는가

같은 문제에 묶인 기록이 서로 다른 주행에서 2건 이상이면 겹치는 범위를 잠정 패턴으로 등록하고 자동 알림을 켭니다. 2건은 확정이 아니라 알림 기준을 만드는 최소 조건입니다. 하루 2회·쿨다운 10분을 넘으면 알리지 않습니다.

3단계 · 사용자 확인

운전자가 증상을 느꼈는가

차곡은 소리를 수집하지 않으므로 소리가 났는지를 검증하지 않습니다. “느꼈어요 / 느끼지 못했어요 / 확인하지 못했어요” 세 답만, 정차 후에 받습니다. 주행 중에는 답을 요구하지 않습니다. 답이 없으면 미확인으로 두고, 미확인은 어느 쪽으로도 세지 않습니다.

상태는 두 줄기로 나눕니다

증상 사건(Issue): 새 증상 → 확인함·미해결 → 정비·수리 후 확인 → 해결 ↩ 재발.
조건 프로파일(ConditionProfile): 조건 없음 → 후보(1건) → 잠정 패턴(2건+) → 알림 활성·조정·중지. 프로파일은 느낌·못 느낌·미확인 세 카운트를 가집니다.
증상은 미해결인데 조건은 충분히 관측됐을 수 있고, 수리는 끝났는데 수리 후 조건을 검증 중일 수 있습니다. 여러 기록이 하나의 Issue에 붙고, ConditionProfile은 그 Issue에 귀속됩니다.

주행 중 안내 원칙

  • 조건 진입: 짧은 음성 한 마디 또는 상단 아이콘. “조건을 지나고 있어요”까지만
  • 주행 중 입력 요구 없음. “기록해” 발화만 받음. 났는지 묻는 건 정차 후
  • 상세 화면·버튼은 신뢰할 수 있게 정차를 확인한 뒤에만
  • 같은 문제 하루 2회(차량 현지 날짜 기준), 쿨다운 10분. 다른 문제가 겹치면 먼저 기록된 것만
  • 주행 규제(CarUxRestrictions)·오디오 포커스·앱 카테고리별 허용 범위를 P0에서 Pleos 가이드와 대조

속도가 없는 이유

2026-10-19 SDK 릴리스 노트에서 Vehicle SDK v2.3.2의 VehicleSpeedListener가 제거되었습니다. 별도 AAOS API 접근 가능 여부와 권한·심사 정책은 공개 자료로 확정할 수 없어 P0 검증 전까지 속도는 제외합니다.

03 · 시연

한 가족, 한 대의 차, 한 사건

장면을 눌러 차량 화면을 바꿔 보세요. 인물·신호·수치는 가상이며, 실제 차량·마이크·계정에 연결하지 않습니다. 음성 SDK가 준비되지 않으면 같은 흐름을 정차 중 화면 버튼과 주행 중 아이콘 알림으로 시연합니다.

차곡 · 우리 차
  1. 민지가 주행 중 “방금 그 소리 기록해”라고 말하고, 앞 20초·뒤 10초의 차량 상태가 저장됩니다.
  2. 준호가 다음 날 탈 때 정차 중에 민지의 기록을 듣습니다.
  3. 수요일, 준호가 알림을 켜 둔 상태에서 같은 조건에 들어가기 직전 차가 “지난번 그 조건이에요”라고 먼저 말합니다. 준호도 기록하고, 다른 주행의 2건이 겹쳐 잠정 패턴이 생성됩니다.
  4. 금요일, 자동 알림에서 준호가 세 번째 기록을 남기고, 정비 리포트가 3건의 관측 조건을 정리합니다.
  5. 패드 교체 후, 같은 조건을 지날 때 차가 “확인 조건을 지나고 있어요”라고만 알리고, 정차 후 “느꼈어요 / 느끼지 못했어요 / 확인하지 못했어요”를 묻습니다.
  6. 준호가 해결로 기록하면 민지의 다음 탑승 브리핑 첫 줄로 전달되고, 관리 이력으로 남습니다.

기록 수: 화요일 1건 → 수요일 2건(잠정 패턴) → 금요일 3건(리포트). 시연을 줄여야 하면 1·3·6번만 남깁니다. 기록 → 차가 먼저 말함 → 처음 기록한 사람이 결과를 들음, 이 세 장면이 전부입니다.

04 · 현대자동차그룹이 얻는 것

원격 진단과 체감 증상 사이의 공백을 보완합니다

블루링크 선제케어는 차량 데이터를 실시간으로 감지해 이상 징후를 안내하지만, 원격으로 확인할 수 있는 데이터에 한해서입니다. 경고등이 켜지지 않는 소리·떨림·느낌은 운전자만 알고, 발생 조건과 함께 기록되지 않습니다. 차곡은 그 공백을 메워 간헐 증상을 정비 과정에서 쓸 수 있게 합니다.

누가무엇을 얻나근거 상태
운전자·가족정비사에게 증상을 설명하는 시간이 줄고, 미해결 증상이 운전자 사이에서 누락되지 않습니다.가설 · 지표: 설명 소요 시간, 미해결 누락 비율
서비스센터재현 조건을 알고 점검을 시작합니다. “일단 타 보시고 또 나면 오세요”가 줄어듭니다.가설 · 지표: 조건 이해 시간, 리포트만으로 재현 시나리오 설정 가능 여부, 같은 증상 재방문 비율
현대차 품질 부서동의한 사용자의 가명·집계 데이터로 차종·연식·주행 상황별 반복 체감 증상을 파악합니다. 흐름: 차량별 체감 증상 수집 → 반복 패턴 비교 → 품질 검토 우선순위 보조 → 조사 대상 선정. 증상·조건·실제 정비 결과가 연결되어야 쓸 수 있고, 데이터 자체가 결함을 증명하지는 않습니다.후속 확장 · 동의·가명처리·집계 정책 필요
블루링크 · 디지털 키디지털 키 공유가 ‘키’만 넘기는 것을 ‘차의 사정’까지 넘기는 것으로 넓힙니다.제휴 가설
인증중고차출처가 구분된 관리 이력(사용자 입력 / 차량 수신)을 차량과 함께 넘길 수 있습니다.후속 확장

위 효과는 모두 검증할 가설이며 성과가 아닙니다. 초기 표본(정비사 2~3명, 가족 3~5가구)으로는 정비 시간 단축이나 재방문 감소를 결론 내릴 수 없으므로, 8장의 지표로 사용자 검증과 사업 효과 검증을 분리합니다. 공모전 시연에서는 “이런 데이터가 생긴다”까지만 보여줍니다.

04-1 · 데이터 처리 원칙

차 안에서 처리하고, 보낼 때는 사용자가 고릅니다

기본

신호 수집, 조건 분석, 사건 기록은 차량 앱 안에서 처리하고 로컬에 암호화 저장합니다. 외부 AI에 차량 데이터를 보내지 않습니다. 내비 정보는 도로 유형과 안내 상황(직진 안내 중, 회전 안내 전후)만 저장하고, 좌표·도로 구간·경로 이력은 저장하지 않습니다. 음성 없는 모드는 ① 주행 중 최근 10분(초안)을 메모리에서만 순환 보관 → ② 정차 후 사용자가 시점 선택 → ③ 그 시점의 앞 20초·뒤 10초만 추출 → ④ 30초만 암호화해 정식 기록으로 저장 → ⑤ 나머지 임시 데이터 폐기. 메모리의 10분과 저장되는 30초를 구분합니다.

사용자 선택

정비 리포트를 공유할 때만, 사용자가 고른 항목을 전송합니다. QR·링크는 만료 기간을 두고 접근을 회수할 수 있습니다. 이미 내려받은 사본의 삭제는 보장하지 않습니다.

가족 공유

조건 분석은 운전자 식별이 필요 없습니다. 기록의 작성자 표시는 프로필, 다른 운전자의 기록 열람은 공유 권한이 필요합니다. 첫 버전은 프로필 선택 + PIN.

향후 확장

차종별 증상 통계는 별도 동의와 가명처리·집계 정책을 거친 뒤에만 활용합니다. 차량 소유자와 실제 운전자를 구분합니다.

Pleos 공식 보안 가이드의 민감 차량 정보 암호화·저장·로그 관리 요구와, 차량 공유 환경의 계정 전환·최소 수집·ID 익명화 요구를 P0에서 대조합니다. 보존 기간과 삭제는 기록 종류별로 정합니다.

05 · 운전 성장은 한 줄로

탑승 브리핑에 배지 한 줄, 나머지는 확장

v2의 코스·가중치·XP는 습관 항목이 셋 이상 검증된 뒤에 의미가 있습니다. 지금 검증 후보는 ‘회전 전 방향지시등’ 하나입니다. 첫 버전은 이 한 항목으로 배지 1종만 만들고, 본인이 원할 때 인수인계 브리핑 끝에 한 줄로 보여줍니다.

첫 버전

“준호 · 이번 주 회전 전 신호 20/23회.” 본인에게만 보이고, 켜면 가족 브리핑 끝에 한 줄 공유됩니다. 점수·순위·코스 없음.

확장 (장롱탈출 코치)

습관 항목이 전조등·안전벨트까지 검증되면 경력별 코스와 첫 경험 도장을 엽니다. 이때도 가족 순위는 만들지 않습니다. v2 5~6장을 그대로 확장 설계로 둡니다.

07 · SDK와 구현 조건

받을 수 있는 신호와 판정할 수 있는 일

2026.10.26 SDK 신청 페이지 기준 Vehicle State·NaviHelper는 사용 가능, SpeechToText·TextToSpeech·FusedLocation은 준비 중입니다. 같은 날짜의 SDK 릴리스 노트에는 세 SDK의 버전(v3.3.1, v1.1.3)이 올라와 있어 문서 간 상태가 다릅니다. SDK는 존재하지만 외부 프로젝트에 아직 열리지 않은 것으로 읽고, Playground 프로젝트 화면의 상태를 기준으로 합니다. 세 기둥 모두 Vehicle State와 NaviHelper만으로 동작하도록 설계합니다.

기능연결 후보P0에서 확인할 것
순간 기록Brake (CAR_DRIVE) · SteeringWheel (대표 권한 표에 없음, READ_CAR_STEERING 가능성, 개별 API의 @RequiresPermission 확인) · Odometer (CAR_DRIVE) 트립 시간 · NaviHelper 안내 상황. 메모리 링 버퍼 20초 + 요청 후 10초, 음성 없는 모드는 최근 10분(초안)리스너가 변화 시점에만 오는지 주기적으로 오는지. 각 콜백에 앱의 단조 증가 시계로 타임스탬프를 붙여 정렬하고, 유지 시간은 ON·OFF 시각 차로 계산하되 중간 누락은 유지로 치지 않음. 주행 중 백그라운드 수집, 차종 capability. NaviHelper 이벤트는 Navigation 앱 구현에 따라 달라지므로 안내 상황 유형을 실제로 받을 수 있는지 확인
재현 알림같은 신호 + 차 안 3단계 규칙. 조건 = 브레이크 유지 시간 + 조향 범위 + 내비 안내 상황. Issue와 ConditionProfile 분리. 속도 없음조건 일치·불일치 시나리오 테스트, 오탐률, 안내 없는 주행에서의 문턱. 주행 규제·오디오 포커스 정책 확인
탑승 브리핑Fuel / EvBattery (CAR_ENERGY), Odometer (CAR_DRIVE), 사용자 입력차종 capability, 정차 확인 경로. 운전자 확인은 프로필 선택 + PIN으로 시작
정비 리포트차량 앱 로컬 집계, QR·링크 공유공유 시에만 서버 업로드. 위치·이동 이력은 기본 제외
습관 배지 (한 줄)TurnSignal (CAR_LIGHTS) · SteeringWheel · NaviHelper 회전 안내회전과 차선 변경·비상등 구분. 검증 전에는 가상 데이터로만 표시
가장 큰 기술 리스크는 속도 없이 조건을 얼마나 좁힐 수 있는가입니다. SDK 릴리스 노트(2026-10-19)에 Vehicle SDK v2.3.2의 VehicleSpeedListener 제거가 기록되어 있어 해당 리스너는 쓰지 않습니다. 별도 AAOS API 접근과 권한·심사 정책은 공개 자료로 확정할 수 없어 P0 검증 전까지 속도는 제외합니다. 그 밖에 브레이크·조향 리스너의 갱신 주기, 이벤트 시각 정합, 주행 중 수집 가능 여부, 음성 SDK 제공 시점, 주행 규제 정책, 가족 간 권한 설계가 각각 P0 확인 항목입니다. 어느 하나도 가정으로 두지 않습니다.

SDK 제공 상태 · SDK 릴리스 노트 2026-10-19 · SDK·AAOS 정책 · Vehicle 권한 표는 도메인별 대표 권한이며 세부 API마다 다를 수 있다고 안내합니다. SteeringWheel은 이 표에 없어 registerSteeringWheelAngle의 @RequiresPermission을 P0에서 직접 확인합니다. 권한 누락 시 onFailed에 VehicleException(ERROR_SECURITY_PERMISSION)이 옵니다. 같은 릴리스에 TelltaleData·Telltales 모델과 getVINInfo가 추가되어, 경고등의 권한 등급은 다시 확인할 가치가 있습니다. 버전 표기(Vehicle SDK v2.3.2, Vehicle Service v2.3.21, FusedLocation v1.1.3)는 2026.11.05 국문 페이지 기준이며, 페이지·언어별로 다르게 표시된다는 지적이 있어 제출 전 Playground 프로젝트 화면에서 재확인합니다.
